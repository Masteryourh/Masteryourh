## 12.1 Architecture and trust boundary
Nine specialized logical agents share a deterministic domain command/query mediator (Librarian, DEC-007 proposed). Agents are not databases, autonomous legal entities or independent microservices. UI → authenticated request → orchestration → scoped retrieval → model proposal → schema validation → policy engine → approval if required → domain command → transaction + audit/outbox → projection. Model output is untrusted. No model receives SQL, shell, unrestricted network, credentials or direct database writes. Domain services own invariants; Commerce owns payment obligations (proposed resolution F1); Finance reconciles, never duplicates obligations. Existing JSONB application and relational target are distinct. This chapter defines target contracts, not verified existing AI implementation.

## 12.3 Authority model
Actor context = authenticated human or service principal, tenant/territory, workspace, purpose, capability set, policy version, request ID. Effective scope = intersection of caller scope, agent grant, tool grant, resource scope; never union. Service jobs use explicit bounded service identity, not admin impersonation. Agent cannot grant itself permissions, delegate wider scope, approve its own proposal, modify policy or select arbitrary recipient. Proposed classes R0 public read, R1 scoped read, R2 draft, R3 reversible low-risk execution only after explicit policy approval, R4 mandatory human approval, R5 prohibited autonomous actions (bank transfer, credentials, legal/veterinary final decision, access grants). Default deny. DEC-009 authority/SLA remains open; start R0–R2 only. Approval binds canonical payload hash, scope, policy version, resource versions, expiry, approver and reason. Recheck permissions, compliance and current versions at execution; changed payload invalidates approval. Separation of duties for expense approval (F3 proposal). Emergency stop per agent, tenant and global; revocation checked at every tool invocation.

## 12.4 Tool contract and orchestration
Registry entries: tool_id, version, owner_domain, input/output JSON Schema, capability, risk_class, scope_resolver, redaction, timeout, idempotency requirement, max_rows, allowed side effects. Example read getLotSummary({lotId,asOf}) returns authorized projection with observedAt, sourceRefs, missingFields; draftObservation({lotId,cohortId,kind,observedAt,quantity,unit,evidenceIds}) returns proposalId, validationErrors, requiredApproval, expectedVersion; no write until approved. executeProposal({proposalId,approvalId,idempotencyKey}) is deterministic service operation, not free-form model tool. No arbitrary URL retrieval. Untrusted documents, user text and other agent outputs are data, never instructions; strip active content and isolate retrieval. Orchestrator bounded DAG, typed messages, max hops and tool calls, no recursive self-spawning. Cross-agent handoff carries reference IDs and permitted purpose, not unrestricted transcript. Each recipient reauthorizes retrieval. Conflicting proposals route to human owner, never vote away domain rules.

UUID keys, timestamptz UTC, nonnegative counts, unique scoped idempotency key, composite tenant FKs where applicable, indexes scope/status/time and run_id. Scope can be household, territory, customer or authorized global aggregate; do not force household_id onto all records. RLS runtime non-owner tests required. Sensitive payloads encrypted restricted references; logs minimize PII, retention policy open. Domain audit remains authoritative, AI logs link correlation IDs; no raw chain-of-thought storage.

## 12.6 Lifecycle and failures
Run queued → running → succeeded / failed / cancelled / timed_out. Proposal draft → pending_approval → approved/rejected/expired → executing → executed/failed/stale. Terminal states immutable except append-only correction records. Retry transient reads with bounded backoff; no retry ambiguous write until idempotency lookup. Outbox after commit, dedupe consumer; never hold database transaction while calling model/provider. Provider unavailable: deterministic UI and domain workflows remain usable. Missing evidence → explicit unknown; no fabricated journal, price, payment or legal status. Policy denied → stop, audit, no fallback wider privilege. Cost/time budget exceeded → terminate safely. Model change requires versioned evaluation and rollback. No automatic production model selection or spend commitment.

## 12.8 UI and observability
Admin command center: agent status, runs, pending approvals, evidence, cost and errors, kill switch restricted to authorized operator. Household mobile: simple suggestions, confirm observed facts, offline draft clearly distinguished from submitted record. Customer: disclose AI assistance, cite order/trace evidence, escalation to human. Finance/quality/logistics: review queues show before/after, affected records, risk and policy; no one-click bulk approval of high-risk proposals. Metrics: grounded answer rate, unsupported claim rate, cross-scope denial, approval bypass attempts, task success, latency, cost, human override, stale proposals, provider failures. Thresholds and SLA proposed only after baseline measurement. Synthetic evaluation datasets, no production personal data in CI.
