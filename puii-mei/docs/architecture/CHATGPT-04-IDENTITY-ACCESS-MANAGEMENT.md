# 04 — Sistemul de utilizatori și permisiuni (IAM-001)
v0.1 DRAFT. CONFIRMAT = mandat/decizie fondator; PROPUS = contract tehnic; DESCHIS = decizie. Surse: PR58, ADR009, NAV001, AUD001, PR62 comentarii 7144648431/7144750950, PR64/66/68/70/73, capitolele 01–03. Nu autorizează implementarea.
## 1. Audit as-built
Main inspectat: src/server/auth.ts requireRole acceptă admin indiferent de lista rolurilor; acesta este un bypass de rol explicit, nu dovadă de acces neautorizat la obiect. În țintă eliminăm bypass-ul implicit; admin primește capabilități explicite. src/server/mfa.ts confirmă TOTP AES-GCM derivat din SESSION_SECRET, lastStep atomic, 5 încercări/15min prin hitRateLimit; contorul se apelează înainte de verificare, deci nu îl descriem drept exclusiv încercări greșite. Rotația secretului de sesiune afectează decriptarea. PR66 raportează 5 teste IDOR și matrice 20 acțiuni/7 citiri, nu dovedește RLS. PR64 raportează PIN curier single-use și sessionVersion. PR70 audit atomic încă deschis. Inventarul complet session.ts, token, toate actions/routes și role checks rămâne necesar.
## 2. Model de autoritate
Principal = identitate umană, agent AI, sistem sau integrare. Actor = principal care execută efectiv; subject = persoana/resursa vizată; onBehalfOf = gospodăria reprezentată, numai cu mandat valid. Rol = pachet de capabilități; grant = drept explicit cu scope, perioadă, sursă și condiții; delegare = subset revocabil al autorității delegatorului, fără amplificare. Workspace nu este rol. Admin național vede informațiile operaționale conform mandatului fondatorului, nu secretele, parolele sau dreptul de a modifica orice. Autoritatea tehnică nu creează mandat juridic.
CONFIRMAT: gospodar → manager local (o comună UAT) → manager zonal (comune din circumscripția unei judecătorii) → admin. Ierarhia este de supraveghere, nu moștenire automată a tuturor drepturilor. Manager zonal nu devine gospodar și nu confirmă implicit plăți. AI automatizează tot ce este permis; lista acțiunilor cu aprobare umană DESCHISĂ.

## 4. Catalog și evaluare
Capabilități tipizate: household.read, production.observation.create, task.read, task.justify, task.justification.review, task.escalate, order.read, order.allocate, finance.payment.reconcile, finance.bank.request, finance.bank.verify, finance.settlement.approve, compliance.evidence.review, compliance.hold.release, logistics.delivery.confirm, identity.grant.manage, audit.read, audit.export, ai.proposal.approve. Separă read/export, propose/approve/execute, câmp sensibil și acțiune.
authorize(ctx, capability, resourceRef) -> Allow{scope,fieldMask,policyVersion,obligations} | Deny{internalReason}. Context server: principalId, actorType, sessionId, membershipIds, workspace, authenticationLevel, requestId. Scope efectiv = intersecția grant activ, mandat aplicabil, atribuiri teritoriale, ownership, stare resursă, condiții și limite delegare. Deny implicit; granturi multiple pot acorda capabilități distincte, fără combinarea scope-ului unui grant cu acțiunea altuia. Explicit deny și hold au precedență. Hold nu blochează automat raportarea incidentului sau accesul la suport.
Citire: filtre autorizate în SQL înainte de paginare/agregare, proiecție allowlist; count/search/autocomplete/export/fișiere/abonamente folosesc aceeași politică. Scriere: verificare în tranzacție pe obiectul actual, lock/version și revalidare mandat/hold; grant revocat nu se reutilizează din cache. Cache key include principal/scope/policyVersion; revocare critică verificată la primary. Nu accepta actorId, role, householdId sau zonă din client drept autoritate.
## 5. Teritoriu și sarcini
Nomenclator UAT SIRUTA, zone după circumscripții, versiuni și intervale fără suprapunere; sursa oficială și procesul de actualizare DESCHIS. Atribuire manager local la o comună, zonal la o zonă; validare cardinalitate activă per manager conform deciziei, înlocuitori temporari PROPUS. Mutarea gospodăriei sau schimbarea nomenclatorului recalculează accesul curent; păstrează istoric fără acces automat al fostului manager. Gospodar justifică sarcina proprie; manager local primește notificare și evaluează; zonal vede justificări și rezolvări; admin vede național. Review, rezolvare și escaladare auditate; SLA și termen reacție DESCHISE. Nu hardcoda județul drept zonă.

## 7. Autentificare și sesiuni
PROPUS: sesiune server-side revocabilă, cookie Secure HttpOnly SameSite adecvat, CSRF pentru mutații, rotire la login/elevare, expirare idle/absolute pe risc; durate DESCHISE. Parole Argon2id sau echivalent validat; rate limit persistent pe cont/resursă/IP, fără blocarea colectivă NAT. Client și curier: păstrează fluxul PIN existent până la ADR de migrare; challenge legat de resursă și scop, expirare, consum atomic, sessionVersion. Recuperare fără enumerare cont, notificare canal cunoscut, verificare identitate, revocare sesiuni și audit. Reset MFA nu este bypass de IBAN; propunere re-enrollment și control suplimentar pentru acțiuni sensibile. MFA obligatoriu pentru roluri privilegiate PROPUS, admin env fără MFA de eliminat prin migrare controlată. Cheie MFA separată de SESSION_SECRET, key_id, rotație cu recriptare; nu pierde accesul prin rotație neplanificată. Break-glass separat, durată limitată, aprobare și audit extern propuse.
ADR009 CONFIRMAT conform PR61/68: schimbare IBAN existent MFA + 24h + notificare + confirmare telefonică, fără autoaprobare; cont vechi activ până la finalizare. Primul cont are confirmare telefonică, fără așteptare conform implementării PR61; MFA pentru primul cont rămâne decizie de clarificat. Nu extinde automat excepția la alte operațiuni.

## 9. Audit, revocare și RLS
Evenimente grant.created/revoked, delegation.created/expired, session.started/revoked, auth.failed, mfa.enrolled/reset, authorization.denied, sensitive.read/export, task.justification.reviewed. Actor real, scope, requestId, policyVersion, rezultat, motiv redactat. Nu PIN, token, secret TOTP, IBAN integral. Scriere business+audit+outbox atomic; refuz separat după rollback. Revocare grant invalidează sesiunea/capability cache relevantă, stream subscriptions și joburi AI pending; worker reautorizează înainte de efect. RLS rol runtime non-owner NOBYPASSRLS, context SET LOCAL tranzacțional, politici tenant și multi-scope; fără SQL arbitrar din UI. RLS nu rezolvă field masking; proiecții și grants separate. Teste pe rol real, nu owner.
