# 16 — UX DESIGN
Version 0.1 DRAFT — 2026-11-26. Source: founder requirements PR58 §16, PR50, PR62 and PR82 review findings as reported. All target designs PROPUS unless explicitly confirmed. No production changes. Existing code not exhaustively audited for this chapter.

## Navigation and roles
Public: catalog, program explanation, availability, preorder, support. Customer: orders, contract versions, payment instructions/evidence, trace, support. Household mobile: Astăzi, loturi, jurnal, materiale, cheltuieli, documente, istoric. Local manager: commune tasks, visits, justifications, incidents; zonal: district overview and escalations. Admin command center: households, production, orders, finance, logistics, quality, users, AI, diagnostics, audit. Finance/logistics/quality dedicated queues. Navigation is projection of server capabilities, never authorization. Admin can act from admin context without impersonation; preserve return route, filters and pagination.
## Components and forms
Design tokens for spacing, type, contrast, status, focus; consistent buttons, field labels, tables/cards, confirmation dialogs, timeline, evidence uploader, status chips. Mobile single-column primary action, numeric keyboard for count/weight, units explicit, large touch targets. Forms show required fields, inline errors and summary; server errors mapped to field or global message. No hidden defaults for unknown mortality/expense values. Draft vs submitted vs approved distinct. High-risk confirmation shows affected resource, before/after, reason and approval requirements. Never optimistic final success for payments, allocations, holds or contracts.
## Daily journal flow
Select lot/cohort → enter actual count/feed/weight/mortality or explicit not measured → evidence → review → submit with clientEventId → server validates → accepted or reconciliation needed. Offline queue encrypted where supported, local draft status, retry idempotent, conflicts show server version and human resolution; no offline approval or financial closure. Record biological deaths after day21 regardless of economic policy.
## States and accessibility
Loading skeleton with accessible status; empty state explains next action; errors distinguish retryable, permission denied and stale version; no sensitive details. WCAG 2.2 AA target, keyboard navigation, visible focus, semantic headings, screen reader labels, contrast, no color-only status, reduced motion, responsive 320px upward. Romanian default, locale-aware numbers/dates, translation keys for future locales. Time zone Europe/Bucharest display, UTC storage.
