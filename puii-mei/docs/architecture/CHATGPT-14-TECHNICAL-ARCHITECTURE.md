# 14 — TECHNICAL ARCHITECTURE
Version 0.1 DRAFT — 2026-11-26. Source: founder requirements PR58 §14, PR50, PR62 and PR82 review findings as reported. All target designs PROPUS unless explicitly confirmed. No production changes. Existing code not exhaustively audited for this chapter.

## Stack and boundaries
Existing Next.js/TypeScript and PostgreSQL JSONB store are baseline context, not exhaustive inventory. Proposed modular monolith: public/admin/household/customer UI → server actions/REST → IAM → domain mediator → domain repositories → PostgreSQL. Separate worker for durable jobs only when runtime requires it. No microservices by default. React server rendering for reads, client components for interaction; never ship privileged payloads to browser. Shared schemas at adapter boundaries; typed repositories and explicit SQL transactions for critical invariants. ORM choice open; no ORM bypass of RLS or transaction semantics.
## Data and performance
Relational migration gated by R01–R07 and reconciled schema. Pool bounded by measured concurrency and provider limits; transaction-local identity reset, no leaked tenant context. Keyset pagination, indexed predicates, SQL aggregates; EXPLAIN ANALYZE on synthetic representative data. Cache public catalog and versioned projections only; key includes scope/policy version; no cached authorization or stale compliance gate. Read model /cifre rebuildable, watermark and freshness displayed. No full collection scan in hot paths. Audit partitioning proposal requires integrity proof and real RTT.
## Files and jobs
Private object storage adapter: create upload intent, size/type allowlist, checksum, quarantine, scan, verified metadata, short-lived signed access after authorization. No public buckets or sensitive file URLs in logs. Outbox worker claims bounded batches using SKIP LOCKED, lease expiry, retry jitter, dead letter, manual replay audited; external email/SMS/model calls outside transactions. Notification preferences and legally required messages separated; templates versioned, recipient masked, delivery receipt not proof of legal acceptance. Provider selection and spend open.
## Observability and recovery
Structured logs request/correlation ID, domain, latency, safe error code; metrics p50/p95/p99, pool saturation, query counts, outbox age, error rate, storage failures, audit integrity. Alert owner and runbook; no raw PII. Backup encrypted, restore into isolated environment, verify counts, checksums, constraints, audit chains and application smoke tests. C4 external backup deferred; local synthetic restore allowed; RPO/RTO not approved. Manual workflows remain available on AI outage.
