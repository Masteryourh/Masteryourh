# 15 — SECURITY
Version 0.1 DRAFT — 2026-11-26. Source: founder requirements PR58 §15, PR50, PR62 and PR82 review findings as reported. All target designs PROPUS unless explicitly confirmed. No production changes. Existing code not exhaustively audited for this chapter.

## Threat model
Assets: identities, bank details, contracts, customer addresses, production evidence, financial ledgers, audit, secrets. Threats: compromised household/admin, cross-tenant IDOR, injection, CSRF, XSS, SSRF, credential stuffing, malicious uploads, AI prompt injection, insider manipulation, replay and supply-chain compromise. Trust boundaries browser/API, worker, DB, storage, providers. Default deny and least privilege.
## Controls
Server derives actor and scope from authenticated session; every resource access checks capability + scope. RLS FORCE where appropriate, non-owner runtime role without BYPASSRLS; composite tenant FK and explicit global-resource exceptions. Test R01–R07 before migration. Session secure HttpOnly SameSite cookies, rotation after privilege change, revocation and bounded lifetime; MFA for privileged actions, recovery audited, no plaintext TOTP secrets. Separate encryption keys from session secrets, key_id and rotation plan. IBAN changes require approved workflow, step-up and cooling policy; never AI autonomous. Independent approval for expenses and sensitive actions; payload hash/version bound.
Parameterized SQL, schema validation, output encoding, CSP, origin/CSRF, rate limits, safe file handling, outbound allowlist. TLS in transit, encrypted storage/backups, restricted key access. Secrets in environment secret manager, never repo or logs; scan commits and dependencies, pin CI actions, least privilege tokens. No real customer data in test environments.
## Audit and privacy
Append-only domain audit atomic with writes; hash chain integrity not confidentiality. Proposed per-household + typed global chains, deterministic lock order, signed manifest chain inventory/count/head, per-chain watermark, external independent anchor, declared unanchored window, key rotation and signed restore. No claim of tamper-proof before anchor; no implementation until integrity and performance proof. GDPR inventory purpose/legal basis/retention/access rights, export and deletion workflow with legal holds, minimize immutable PII by references and controlled pseudonymization. Legal validation and retention durations open.
## Incident response
Detect, classify, contain (revoke sessions/keys, suspend capability), preserve evidence, assess impact, notify responsible human/legal team, recover and postmortem. Do not automate statutory determinations. Security gate blocks sensitive rollout until critical findings closed.
